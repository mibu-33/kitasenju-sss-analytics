## 2026-10-19 自動取得の実績と第二経路

- **自動取得に成功**: スロナビ公開日別ページ `https://slo-navi.com/data/YYYY-MM-DD-11400/` から、北千住SSSの台番・機種名・差枚・ゲーム数・BB・RBを取得。
- 1営業日につき451台の実データがあることを検証し、`data/records.json` と `data/summary.json` に出典 `slo-navi` を明記して保存。451台に満たないページは保存しない。
- スロレポの自動取得は引き続き HTTP 403。スロレポから取得できた旧データと、スロナビから取得した新データの差枚指標は**集計方法が異なる可能性があり、無条件で同等とみなさない**。
- GitHub Actionsが毎日JST 9・10・11時に起動し、直近の未取得日を優先、その後2026-07-08まで未取得日を1回最大12日ずつ補完する。取得元のrobots.txtに従い、アクセス拒否時は停止。VPNは不要。
- 確認は `data/status.json` の `fallback_last_success`、`fallback_indexed_days`、`fallback_newest_date` を参照。最終取り込みの成功はGitHubの実行結果で確認する。
- サイト側の更新遅延や廃止により、取得を保証するものではない。主な集計対象は日々の台番・差枚・G数。高設定を実測で確定する機能ではない。

## 実装機能

- 店全体：日別平均差枚・勝率・平均G数、直近30/90日・全期間、旧イベント日（6のつく日）、日付末尾・台番末尾
- 機種別：台別記録からの分析と、スロレポの機種別日次集計の**両方**に対応。機種の平均差枚は設置台数を重みとして集計
- 台番号別：日付ごとの機種変更を `(営業日, 台番号)` の履歴として保持。平均差枚・勝率・ヒートマップ
- 実島図：通路名（A/B/...）、左右（左/右）、列内の位置順、適用開始日・終了日。通路左右・3台並び・台間位置関係を分析
- おすすめ / ローテーション：公開告知を確認したユーザーが日付・対象機種 / 台番を入力し、過去実績と突合・同機種の非対象日と比較
- 参考ランキング：機種の過去実績を観測日数で縮小補正（設定推定ではありません）。除外キーワード対応
- CSV出力・島図JSON出力・イベントJSON出力・端末への設定保存・PWA
- GitHub ActionsによるJST 9/10/11時の取得、VPNオプション、取得失敗・更新遅延の表示

## 1. 既存アプリと別に公開する手順

1. GitHubで **`kitasenju-sss-analytics`** という独立リポジトリを作成（Public を推奨。データを非公開にしたい場合は Pages 公開条件も確認）。
2. ZIPの中身（このREADMEがルートにある状態）をそのリポジトリの `main` にアップロード。
3. Settings → Pages → Build and deployment → Source = **GitHub Actions**。
4. Actions → **SSS Data Sync and Deploy** → **Run workflow** を一度実行。成功後に Settings → Pages のURLで表示できます。
5. 以降、JST 9:00 / 10:00 / 11:00 に自動取得。ただしGitHubの定期実行は遅れることがあります。

**GitHub Actionsの最初の実行が失敗した場合**：Actionsログと `data/status.json` を見てください。サイト側が応答しない / Excelを提供しない / 日別レポートの構造が変わった場合は空欄のまま残り、値を捏造しません。

## 2. ローカルで起動

```bash
python -m pip install -r requirements.txt
python scripts/sync.py     # サイトに接続可能な場合だけ（未接続環境では失敗）
mkdir -p site
cp -r public/. site/
cp -r data site/data
cd site
python -m http.server 8080
```

ブラウザで `http://localhost:8080` を表示。Windowsならフォルダコピーをエクスプローラーで行っても構いません。

## 3. 台別のRAW Excelデータが自動取得できない場合

スロレポから入手が許可されたExcel/CSVの原本を、ローカルでインポートできます。

```bash
python scripts/import_local.py ~/Downloads/table_data.xlsx
# または UTF-8 CSV: 日付,台番号,機種,差枚,G数,BB,RB
python scripts/import_local.py ~/Downloads/sss.csv
```

日付が列やシート名になく区別できない台別レコードは取り込みません。RAW Excel が店全体・機種別の集計だけなら、台別解析はできません。データを公開したい場合は `data/records.json` をコミットしてください。

## 3.1 GitHubにファイルをアップロードするだけで自動取り込み（新機能）

1. スロレポの店舗ページに、利用条件の範囲でご自身のブラウザからアクセスして、**分析用RAWデータ（Excel）**をダウンロードします。クラウド側の403をVPN等で回避する目的ではありません。
2. [imports/へアップロード](https://github.com/mibu-33/kitasenju-sss-analytics/upload/main/imports) から、日付付きの台別ExcelまたはCSVを登録します。**GitHubリポジトリは公開設定なので、データの再配布が許諾されているか確認してください。**不明な場合はアップロードせず、個人PCだけで`python scripts/import_local.py`を使ってください。
3. pushを契機にGitHub Actionsが自動実行し、日付・台番号を検証して`data/records.json`を更新、Pagesへデプロイします。
4. `data/imported_files.json`に内容ハッシュを保存し、同一ファイルの二重取り込みを防ぎます。後日の台移動も日付×台番号で区別します。

CSVヘッダー例：`日付,台番号,機種,差枚,G数,BB,RB`。集計行だけや日付がない台データは取り込みません。小規模な部分CSVから店舗全体の平均は作りません。

## 4. 島図と告知の登録

アプリの「実島図・通路」タブのエディタで台番、通路（例：`A`）、左右（`左` / `右`）、列の位置、必要なら開始日・終了日を入力。CSV一括登録も可能です。

```csv
台番,通路,左右,位置,開始日,終了日
9991,A,左,1,2026-10-01,
9992,A,左,2,2026-10-01,
9993,A,左,3,2026-10-01,
```

上記の番号は説明用の**架空の値**です。実際の配置を表していません。

画面で編集した島図・イベント履歴は**その端末のブラウザ内だけ**に保存されます。共有するときはJSONを出力し、`data/layout.json`、`data/events.json` へ置き換えてコミットしてください。台移動があったら位置の履歴を分けて登録してください。

「おすすめ検証」タブは実際に確認した告知を登録する方式です。スロレポの成績から告知を逆算することはしません。機種名がデータと完全一致することが条件です。

## 5. VPN (オプション)

**利用規約やアクセス制御の回避には使用しないでください。** GitHub Actions上の出口を許可されたVPNへ固定するときに使用します。

1. 自分が利用を許可されているWireGuardの設定ファイルを用意。IPv4のUDPエンドポイントと `AllowedIPs = 0.0.0.0/0` のフルトンネルを使用してください。
2. ローカルで `base64 wg0.conf` 等を使ってBase64化し、GitHub → Settings → Secrets and variables → Actions → Repository secrets → `WG_CONFIG_B64` に登録。
3. 同じページの Repository variables → `USE_WIREGUARD` に `true`。
4. Actions実行時にトンネルを確認し、IPv4・IPv6の他経路をブロックした状態で取得します。接続できない場合は**直接通信へ自動フォールバックしません**。アップロードやデプロイのために終了後は通常経路に戻します。

公開したZIPにVPNの鍵を追加しないこと。VPNの運用と実行可能性は未検証です。サイト側が取得を許可しない場合、VPNにしても処理を中止します。

## 6. 精度と今後の検証

- 機種別集計には台番号を含まないので、台番・通路・隣接台の評価には使用しません。
- 差枚が出た＝高設定ではありません。AT機の短期的な差枚から設定を同定しません。
- 参考スコアは記述統計です。予測確率・期待収支を表示しているわけではありません。実際の設定が分からないため教師データとして利用できません。
- 推定やバックテストをするなら、予測時点で知り得た過去データだけを使って後日評価する別モジュールが必要です。
